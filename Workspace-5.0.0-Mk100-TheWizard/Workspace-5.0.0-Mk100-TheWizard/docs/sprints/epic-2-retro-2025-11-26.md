## Challenges & Growth Areas

### ⚠️ Areas for Improvement

1. **Story Numbering Collision (Stories 2.2)**
   - **Challenge:** Dual stories both numbered "2.2" (conversation-api-persistence.md + document-ingestion-pipeline.md)
   - **Impact:** Ambiguity when referencing "Story 2.2" in planning meetings and documentation
   - **Root Cause:** Manual story numbering without collision detection
   - **Learning:** Use sequential numbering or explicit sub-numbering (2.2a/2.2b) to prevent ambiguity
   - **Action Item:** Update sprint planning workflow to enforce unique story numbers

2. **Deferred LLM Validation Creates Known Risk**
   - **Challenge:** Story 2.5 LLM client built but not tested with live OpenRouter API calls
   - **Impact:** First real LLM integration testing will happen in Epic 3 Story 3.1, risking surprises
   - **Root Cause:** Strategic user constraint ("don't activate yet, too many memories") + pragmatic cost avoidance
   - **Learning:** Deferred validation is acceptable with eyes-open risk acknowledgment, but activation plan must be documented
   - **Action Item:** Validate LLM client with live API before Epic 3 starts

3. **Story Status vs Task Completion Misalignment (Story 2.4)**
   - **Challenge:** Story 2.4 marked status='done' but tasks show incomplete checkboxes (observability, performance validation)
   - **Impact:** Confusion about whether story truly meets DoD; technical debt not explicitly tracked
   - **Root Cause:** Functional requirements met (CLI works), but non-functional requirements (logging, latency checks) deferred
   - **Learning:** Story status='done' must align with task completion OR technical debt must be explicitly logged
   - **Action Item:** Enforce DoD check - "If status='done', all tasks checked OR debt logged"

4. **Integration Test Gap for LLM Client**
   - **Challenge:** Story 2.5 unit tests mock HTTP responses; no integration tests with real API
   - **Impact:** Cost tracking, error handling, provider routing unvalidated in live scenarios
   - **Root Cause:** No API key committed + user constraint to not activate yet
   - **Learning:** When integration testing is deferred, document activation requirements clearly
   - **Action Item:** Document LLM client activation steps (API key setup, cost verification)

## Key Lessons Learned

### What We'll Keep Doing

1. **Follow through on retrospective commitments**
   - Epic 1 action items delivered results (poetry.lock, integration tests, dependencies)
   - Pattern: Retrospectives → Action Items → Execution → Prevention of blockers
   - **Keep:** Track action items, review in next retro, measure follow-through rate

2. **Strategic infrastructure building (last story prepares next epic)**
   - Story 2.5 LLM client exceeded immediate scope to prepare Epic 3
   - **Keep:** "Last story of epic prepares KNOWN dependencies for next epic"
   - **Caution:** Only build dependencies we KNOW we'll need; avoid speculative features

3. **Architecture discipline**
   - All 5 stories traced decisions to architecture.md
   - Version matching, ADR compliance, security-first design
   - **Keep:** Every technical decision must reference architecture/ADRs

4. **Integration test coverage for infrastructure code**
   - Stories 2.2, 2.3 integration tests caught real bugs
   - **Keep:** Unit tests necessary but not sufficient for infra; always add integration tests

### What We'll Start Doing

1. **Explicit story numbering validation**
   - Prevent collisions like dual 2.2 stories
   - **Start:** Validation step in sprint planning workflow; use sequential or sub-numbering

2. **DoD = task completion OR explicit debt**
   - Story status='done' must align with task checkboxes
   - **Start:** Enforce check before marking stories done; use technical debt template for deferrals

3. **Document deferred validation explicitly**
   - Story 2.5 LLM client deferred live testing
   - **Start:** When integration testing is deferred, document activation requirements in README

### What We'll Stop Doing

1. **Marking stories 'done' with incomplete tasks**
   - Story 2.4 had incomplete checkboxes but status='done'
   - **Stop:** No more status/task misalignment; enforce DoD check

2. **Assuming functional=complete**
   - Story 2.4 CLI worked but lacked observability
   - **Stop:** Functional requirements alone don't meet DoD; non-functional requirements (logging, error handling, performance) are required
