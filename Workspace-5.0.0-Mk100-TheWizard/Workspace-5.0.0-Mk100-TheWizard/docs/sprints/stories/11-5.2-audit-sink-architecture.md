> *"Add adapter layer for observability and persistence."*

---

## Story

As a system architect,
I want **a pluggable sink architecture for EpistemicAuditLog**,
so that **audit events can be routed to multiple backends (memory, stdout, database) without changing the semantic core**.

---

## Context

Story 11-5 implemented `EpistemicAuditLog` (AC6) with in-memory storage. For production observability (Graylog/ELK integration), we need a thin sink/adapter layer.

**Key Principle:**
> Keep `EpistemicAuditLog` as the semantic core. It defines *what* an epistemic event is. It should not care *where* events are stored or shipped.

### AC 3: EpistemicAuditLog Refactor

**Given** audit log needs to support multiple sinks
**When** refactoring the core class
**Then** fan-out to all configured sinks

**Implementation:**
```python
class EpistemicAuditLog:
    def __init__(self, sinks: list[EpistemicAuditSink] | None = None):
        if sinks is None:
            self._memory_sink = InMemorySink()
            self._sinks = [self._memory_sink]
        else:
            self._sinks = sinks
    
    def log_event(self, event: EpistemicEvent) -> None:
        for sink in self._sinks:
            try:
                sink.handle_event(event)
            except Exception as e:
                logger.warning("sink_write_failed", sink=type(sink).__name__)
```

- [x] Accept `sinks` parameter in constructor
- [x] Default to `[InMemorySink()]` if none provided
- [x] Fan-out to all sinks with error isolation
