### Challenges & Growth Areas

Bob (Scrum Master): "Now let's talk honestly about struggles. Where did we hit friction?"

#### 1. Mock→Real LLM Transition

Charlie (Senior Dev): "Story 4.2 initially used mock LLM calls for speed. When we integrated real providers in Phase 4, we had to refactor PersonaResponse to include cost and token metadata."

Elena (Junior Dev): "That wasn't a huge lift, but it delayed integration testing. We should have designed for real providers from the start."

Alice (Product Owner): _nods_ "That's a pattern we've seen before. Mocks are useful for unit tests, but integration should happen early."

**Action Item:** For Epic 5+, design schemas to accommodate real provider metadata from day one.

#### 2. Async/Sync Bridge Complexity

Charlie (Senior Dev): "The LLM providers use sync calls, but our orchestrator is async. We needed a ThreadPoolExecutor to bridge them."

Elena (Junior Dev): "I found that confusing initially. The async→sync→async pattern isn't intuitive."

Charlie (Senior Dev): "True, but it's necessary. Most LLM SDKs are sync. We could wrap them in async, but that's reinventing the wheel."

Bob (Scrum Master): "Did this cause bugs or just learning curve?"

Charlie (Senior Dev): "Just learning curve. The pattern works well once you understand it."

#### 3. Database Migration Friction

Dana (QA Engineer): "Alembic migration for the voting_metadata column had a duplicate index definition initially. We caught it in testing, but it required manual cleanup."

Charlie (Senior Dev): "Yeah, that was my mistake. I added the index in both the migration and the model definition. Alembic got confused."

**Action Item:** Use Alembic's auto-detection for indexes instead of manual definitions.

#### 4. MCP Tool Dependencies

Elena (Junior Dev): "Story 4.8's research executor depends on MCP Docker server being available. If MCP is down, autonomous research fails."

Charlie (Senior Dev): "We have fallback logging, but yes - it's a hard dependency. We should consider an HTTP fallback for basic URL fetching."

Alice (Product Owner): "Is that worth doing now, or can it wait?"

Ariel (Project Lead): "Let's defer it. MCP is stable enough for MVP. We can add HTTP fallback in Epic 7 (Web Intake) if needed."

**Decision:** Defer HTTP fallback to Epic 7.

## Team Agreements

Bob (Scrum Master): "These agreements define how we'll work differently going forward."

### Agreement 1: Async-First for I/O-Bound Operations

**What:** All LLM calls, database queries, and web requests use async/await patterns
**Why:** Epic 4 proved 91% latency reduction from parallelism
**How:** Use `asyncio.gather()` for concurrent operations, semaphores for rate limiting
**Applies To:** Epic 5+

### Agreement 2: Real Provider Integration in Integration Tests

**What:** Integration tests use real LLM providers, not mocks
**Why:** Mocks hide integration issues until too late
**How:** Use cheap models for integration tests (e.g., Gemini Flash, Llama 3.2 via Groq)
**Applies To:** Epic 5+

### Agreement 3: JSONB for Evolving Metadata Schemas

**What:** Use JSONB columns for metadata that may evolve (voting, citations, cost)
**Why:** Schema flexibility without migrations for every field addition
**How:** Define JSONB structure in code comments, use pydantic for validation
**Applies To:** Epic 5+ (especially cost ledger)
